# TRACE rank audit output data dictionary

Version: 1.2.1

`OUTPUT_SCHEMA.tsv` is the normative, machine-readable column contract. This
document defines row keys, set semantics, and cross-file invariants. The formal
Supplementary Table S8 is generated as an exact copy of the normative schema.

## Cell sets

For one `context_id × specification_id` cell, let `B` be `budget`, let `H` be
the candidates whose scores are strictly above the tolerance-defined cutoff
boundary, and let `T` be the complete boundary tie block. The number of seats
allocated from `T` is `r = B - |H|`.

- The deterministic realization is `H` plus the first `r` identifiers in `T`
  under ascending candidate-ID order. It is an operational reproduction rule,
  not a biological preference.
- A candidate is **necessary** when it belongs to every legal capacity-`B`
  realization: all members of `H` are necessary, and every member of `T` is
  also necessary when `r = |T|`.
- A candidate is **possible** when it belongs to at least one legal realization:
  every member of `H ∪ T` is possible.
- `boundary_set_valued = 1` exactly when `r < |T|`; only then can legal
  realizations differ in membership.
- `uniform_tie_selection_probability` is 1 for necessary members, `r/|T|` for
  a genuinely set-valued boundary member, and 0 otherwise.

Consequently, for every cell:

- deterministic selected count = `budget`;
- `necessary_n <= budget <= possible_n`;
- `necessary_selected <= deterministic_selected <= possible_selected` for
  every candidate;
- `necessary_selected = 1` if and only if
  `uniform_tie_selection_probability = 1`;
- a non-set-valued boundary has `necessary_n = possible_n = budget`.

## Row keys

- `cell_contract.tsv`: one row per
  `context_id × specification_id`.
- `pairwise_audit.tsv`: one row per unordered
  `context_id × specification_a × specification_b` comparison, with
  `specification_a < specification_b` under lexical ordering. A legal input
  with only one specification in a context produces no comparison row; the
  file is still emitted with the complete `OUTPUT_SCHEMA.tsv` header.
- `target_membership.tsv`: one row per finite-score
  `context_id × specification_id × candidate_id`; omitted only when
  `--skip-target-membership` is explicitly used.
- `audit_receipt.json`: one receipt for the complete command invocation.

## Pairwise quantities

Pairwise intersections and substitutions compare legal capacity-`B` lists
within the same context. `intersection_minimum` and `intersection_maximum` are
sharp over admissible boundary allocations for that pair. The corresponding
substitution bounds reverse direction because substitution equals
`1 - intersection / B`.

`intersection_expected_uniform_tie` assumes independent uniform allocation
within each compared boundary block. It is a declared coupling-specific sensitivity model, not a
model of analyst or expert behavior. `intersection_expected_chance` instead
uses independent uniform capacity-`B` sampling from each complete scored
universe and accounts for the size of their shared candidate set.

## Receipt reproducibility

Normal runs record their real UTC completion time. The committed worked example
uses `2026-08-08T00:00:00+00:00` only as a canonical serialization value so that
`regenerate_example_output.py --check` can verify byte-for-byte reproducibility.
All analytical fields are generated by the same engine used for ordinary runs.
